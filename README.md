# 개인 SEGIO 로그인으로 자료 받기 · v0.6.3

개인 SEGIO 직원 아이디·암호로 본인의 결재 문서와 메일을 폴더에 보관합니다. [v0.6.3 소스 ZIP 다운로드](https://github.com/soriel1004/segio-web/raw/refs/heads/main/downloads/segio-web-0.6.3.zip) 후 Windows에 Python 3.12를 설치하고 `run_windows.bat`을 실행합니다. 창의 **v0.6.3**을 확인하세요. Windows 실행 파일은 [이 저장소의 Actions](https://github.com/soriel1004/segio-web/actions)에서 해당 버전의 성공한 빌드가 있는지 확인한 뒤 받습니다. 기존 `segio` 저장소의 SSH 전용 실행 파일은 별도 프로그램입니다.

프로그램 배포 ZIP 파일명은 `segio-web-{프로그램 버전}.zip` 형식입니다. 현재 버전은 `segio-web-0.6.3.zip`이며, Windows 빌드도 프로그램의 버전 번호를 읽어 같은 이름으로 저장합니다.

첫 화면은 **결재 문서·메일·암호화되지 않은 HTTP 연결 허용**만 기본 선택합니다. HTTPS 주소에서는 인증서 검증을 유지합니다. 개인 로그인 방식은 [서버 연결 기능](docs/WINDOWS_LOGIN.md)이 설치되어 있어야 하며, 서버에는 전송·검증용 임시 ZIP이 필요합니다. 내려받은 뒤 다시 ZIP을 만들거나 최종 ZIP을 추가 저장하지 않고 **백업 폴더만** 남깁니다. SSH 방식의 추가 ZIP도 기본 해제입니다.

첫 화면은 **개인 SEGIO 로그인으로 자료 받기** 전용이며 가져오기 방식 목록을 표시하지 않습니다. 기본 서버는 `lssgroup.co.kr`의 기존 로그인 경로이고, 계정 입력 이름은 **그룹웨어 ID·그룹웨어 암호**입니다.

서버 결재 DB 추출에서 `category: encoding` 오류가 발생하면 [공용 tools의 한글 경로 수정 안내](tools/README.md#결재-db-추출-단계의-encoding-오류)에 따라 서버 도구를 갱신하세요. v0.6.3 묶음의 추출기 표기는 `db-native-paths-1`입니다.

## v0.6.3 메일 HTML 오류·보안 차단 첨부 처리

제공된 JSON의 프로그램은 **0.6.1**이며 직접 중단 위치는 `portable_mail.sanitized_html`의 `unwrap()`에서 발생한 `ValueError`입니다. 같은 시간대 보안 기록에는 추출한 HTML 첨부의 Trojan 검출이 있습니다. 이 JSON은 파일 접근 오류를 기록한 것이 아니므로 두 현상을 같은 원인으로 단정하지 않습니다. 이미 제거된 태그의 자식을 다시 처리하지 않도록 하고, HTML 정리의 해석 오류는 실행 불가능한 이스케이프 텍스트와 확인 항목으로 전환합니다. 과도한 표 병합 숫자도 안전하게 처리합니다.

**새 0.6.3 ZIP을 별도 프로그램 폴더에 풀고 `run_windows.bat` 실행 → 창 제목 v0.6.3 확인 → ‘기존 백업 갱신’ → 오류 당시의 `manifest.json`이 있는 `segio-직원ID` 폴더 선택**으로 복구합니다. 메일 원본이 남아 있으면 서버에 다시 로그인하거나 다운로드할 필요가 없습니다. 이번 수정의 서버 tools는 0.6.2와 동일하므로 이 복구를 위해 서버를 재설치하거나 재부팅하지 않습니다.

메일에서 별도로 만드는 첨부에 Windows 보안 차단 코드 **225/226**이 발생하면 해당 첨부를 미확보로 기록하고 나머지 본문·첨부·메일을 계속 처리합니다. 이미 생성한 첨부가 삭제·격리되거나 바뀐 경우도 미확보로 표시하며, 정확한 원인을 확인하지 못한 경우 바이러스라고 단정하지 않습니다. 첨부 링크 대신 미확보 안내를 표시하고 완료 팝업·‘확인 필요 메일 목록’·manifest에 건수와 이유를 남깁니다. 일반 완료 팝업으로 모든 첨부가 확보됐다고 표시하지 않습니다.

구버전이 첨부를 만든 뒤 HTML 오류로 중단되어 완료 상태 기록이 없는 메일은, 남아 있는 첨부만 원본과 대조해 재사용합니다. 이전 첨부 폴더에서 사라졌거나 확보 여부를 확인할 수 없는 파일은 미확보로 남기고 다시 생성하지 않습니다. 바이러스 격리가 아닌 일반 중단 때문에 완료하지 못했던 첨부도 이 보수적인 복구에 포함될 수 있으며 확인 목록에 이유를 표시합니다.

각 메일의 `attachment-status.json`은 해당 원본 지문·첨부 경로·고정된 이유만 담습니다. 같은 원본을 복구할 때 기록된 첨부를 다시 추출하지 않고, MIME 오류까지 겹쳐도 그 내용을 별도 EML에 다시 복사하지 않습니다. 보안 프로그램 설정·격리 자료·원본 메일을 변경하거나 검출 파일의 확장자/인코딩을 바꿔 우회하지 않습니다. 이 기록은 같은 원본과 메일에 대한 복구용이며 새 원본 전체에 대한 바이러스 검사나 보안 판정을 대신하지 않습니다.

완료된 기존 보관함을 프로그램에서 열 때 첨부 존재·크기와 상태 기록을 확인합니다. 기존 본문·첨부를 전부 다시 읽거나 변환하지 않고 누락된 첨부가 있는 메일만 안내를 갱신합니다. 직접 `index.html`만 여는 동작은 보관 파일을 갱신하지 않습니다. 생성 직후 상태를 다시 확인해도 보안 제품의 비동기 격리가 나중에 발생할 수 있으므로, 보안 보호 기록을 함께 확인해야 합니다. 원본 MBOX·검색 DB·필수 파일이 차단/격리되거나 일반 권한·디스크 오류가 발생하면 정상 완료로 숨기지 않고 중단합니다. 보안 차단의 익명 진단 코드는 `FILE_SECURITY_BLOCKED`입니다.

## v0.6.2 백업 시각 이후 메일만 추출·기존 폴더 반영

**Windows 프로그램과 서버 공용 tools를 모두 0.6.2 묶음으로 갱신**하세요. [서버 설치 명령](tools/README.md#v062-백업-기준-시각-이후-메일-추출)을 실행하고 `Date-selected mail revision: file-time-merge-1.`을 확인합니다. 진행 중인 백업이 끝난 뒤 설치하며 그룹웨어 재부팅은 필요하지 않습니다.

‘처음부터 전체 백업’은 새 폴더에 전체 자료를 보관합니다. **‘이전 백업 이후 추가 · 기존 폴더 반영’**은 정상 완료한 본인의 `manifest.json`이 있는 폴더를 선택합니다. 추가 백업은 그 폴더에 반영하므로 별도의 새 보관함을 계속 만들지 않습니다. 다른 직원·미완료·손상된 메타데이터/검색 DB·메일 없는 최초 기준 백업은 거부하고, 이전 버전에서 만든 백업도 기준 시각·완료 상태·원본 목록·현재 바로보기 형식이 확인되면 사용할 수 있습니다.

메일의 선택 기준은 **서버 파일의 저장·변경 시각(mtime 또는 Linux ctime)이 마지막 정상 백업의 기준 시각 이상인지**입니다. 예전 메일에 대한 답장도 새 파일로 저장되면 포함하며, 메일 헤더의 Date 값으로 추출 대상을 거르지 않습니다. 목록에 표시하는 날짜는 계속 원본 Date 헤더입니다. 서버는 원본 파일 목록·시각을 확인하고, 기준보다 오래된 메일 본문은 열거나 복사·해시·압축하지 않습니다. 새 파일과 이후 변경된 파일만 원본·ZIP 해시 검증 후 받습니다. 여러 메일을 묶은 MBOX 자체가 변경됐다면 해당 파일 전체가 대상입니다.

백업 도중 도착한 자료가 누락되지 않도록 **마지막 정상 백업에서 메일 수집을 시작한 서버 시각**을 다음 기준으로 저장합니다. 같은 초에 저장된 파일은 다음 실행에도 포함할 수 있지만 기존 파일 이름·SHA-256이 같은 자료는 중복 추가하지 않습니다. 구버전에 이 필드가 없으면 서버 추출 요청 시각을 사용하고, 그마저 없으면 완료 시각을 사용합니다. 서버와 PC의 시계 차이가 추출 기준을 바꾸지 않도록 서버 시각을 사용합니다.

PC에서는 기존 메일 원본·검색 ID·바로보기·첨부를 유지하고 추가·변경된 메일만 색인·변환합니다. 검색 목록은 합친 전체 자료로 갱신합니다. 서버에서 사라진 원본 메일 파일·과거 결재는 기존 보관본에서 자동 삭제하지 않습니다. 변경된 MBOX 파일은 그 파일의 현재 내용으로 교체합니다. 결재는 기안일만으로 거르면 예전 문서의 결재 완료·반려·수정이 누락되므로 **현재 DB를 재조회해 문서별로 병합**합니다. 결재 DB 조회 전체가 날짜 필터로 생략되는 기능은 아닙니다.

반영 준비는 기존 폴더와 같은 드라이브의 임시 폴더에서 수행합니다. NTFS처럼 하드 링크를 지원하면 기존 원본·완성된 메일 페이지/첨부는 다시 복사하지 않고 준비 중인 사본과 공유하며, 공유 파일을 덮어쓰지 않고 교체합니다. 지원하지 않는 파일시스템은 공간을 확인하며 복사합니다. 검색 DB·메타데이터는 별도 파일로 작업합니다. 검증·색인·서버 정리 확인이 끝난 뒤 기존 폴더를 교체하고 정상 반영 후에만 다음 기준 시각이 적용됩니다. 중단·준비 오류·폴더 교체 실패 시 기존 백업을 유지합니다. 교체 중 잠금은 오류로 알리고 전원/프로세스 중단은 작은 반영 기록으로 이전 폴더를 복구할 수 있습니다. PC의 `.segio-update-*.lock`은 동시 반영 방지용 작은 파일이며 메일·암호를 담지 않습니다.

## v0.6.1 메일 바로보기 생성 오류·보존한 백업 복구

v0.5.9의 `UNEXPECTED_PROCESSING_ERROR / LOCAL_INDEX_PENDING` 이후 보존한 백업은 새 Windows 프로그램의 **‘기존 백업 갱신’**을 누르고 오류창에 표시된 `segio-직원ID` 폴더를 선택하세요. `manifest.json`이 있는 직원별 폴더를 선택하며 상위 저장 폴더를 선택하지 않습니다. **서버에 다시 로그인하거나 전체 자료를 다시 받을 필요가 없습니다.** 0.6.1 ZIP은 새 폴더에 풀어 `run_windows.bat`을 실행하고 창 제목의 버전을 확인하세요. 이번 PC 수정의 공용 서버 tools는 0.6.0과 동일하므로 서버 재설치·재부팅이 필요하지 않습니다.

잘못 인코딩된 제목·보낸 사람·첨부 파일명은 해석 실패 값을 문자 그대로 표시하고 확인 항목으로 남깁니다. 잘못된 Base64·MIME 구분자·과도한 MIME 중첩·지원하지 않는 전송 인코딩 때문에 메일 한 통을 변환하지 못하면, 해당 메일의 부분 생성 첨부를 정상 결과로 남기지 않고 **원본 바이트 그대로의 EML과 안내 페이지**를 보존한 뒤 나머지 메일을 계속 처리합니다. 원본 MBOX·EML은 수정하지 않습니다. 정상 메일은 기존과 같이 본문·첨부를 생성하고, 중단 전에 완료한 메일 페이지는 검증 후 재사용합니다.

형식 확인 항목이 있으면 완료 팝업과 인덱스에 건수를 표시합니다. **‘확인 필요 메일 목록’**은 `mail/processing-issues.html`로 연결되며 항목별 페이지와 이유를 확인할 수 있습니다. 원본 EML로 보존한 메일은 본문·첨부 자동 변환 완료로 표시하지 않습니다. 기존 파일 접근 거부·저장 공간·메모리·프로그램 오류는 원본을 보존한 오류로 처리하며 손상된 메일 경고로 숨기지 않습니다.

사용자가 제공한 0.5.9 JSON은 PC 색인 단계의 일반 코드뿐이었고, 마지막 로그는 메일 바로보기 생성이었습니다. 이 기록만으로 해당 직원의 정확한 실패 메일·예외를 확정하지는 않았습니다. 코드에서 같은 일반 오류로 이어지는 헤더/첨부 파일명 인코딩과 Base64 예외를 재현해 보완했습니다. 새로운 예상 밖 오류에는 허용된 예외 종류·프로그램 모듈/함수/줄 번호·SQLite 숫자 코드만 추가하며 메일 내용·제목·직원 ID·경로·예외 원문은 기록하지 않습니다. 재발하면 저장 폴더의 새 `last-client-failure.json`으로 실제 실패 위치를 확인합니다.

## v0.6.0 진행 표시·중단 정리·변경분 백업

아래 변경분 설명은 0.6.0~0.6.1의 파일 해시 비교 방식입니다. 현재 0.6.2의 추가 백업은 위의 시각 기준 추출·기존 폴더 반영으로 대체했습니다.

색인 생성 중에도 메일 파일을 읽은 용량·전체 용량·색인한 메일 건수를 표시합니다. 큰 메일 한 통을 스캔하는 중에도 읽은 바이트로 진행바가 갱신됩니다. 메일 원본 준비, 결재 색인, 메일 색인, 검색 DB 저장·검증, 본문·첨부 생성, 검색 목록 생성 단계를 구분합니다. 총량이 없는 작업은 대기 표시를 사용합니다. 완료 팝업은 **‘백업 완료 / 백업이 완료되었습니다.’**로 표시합니다.

**중단**을 누르면 ‘지금까지 진행한 내역이 삭제됩니다’ 확인창을 띄웁니다. 취소하면 백업을 계속하고, 확인하면 이번 실행의 PC 백업·임시 폴더와 서버 작업 파일·폴더를 정리합니다. 이전에 완료한 백업과 그룹웨어 원본은 유지합니다. 서버 작업기는 중단을 처리하고 열린 파일을 닫은 뒤 자신의 작업 폴더를 삭제하며, 연결이 끊겨도 확인받은 자동 정리 요청은 유지합니다. DB 대기 중에는 해당 작업에서 실행한 조회 프로세스만 종료합니다. 클라이언트는 삭제 완료 응답을 확인하며, 연결 불가 또는 20초 내 완료 미확인 시에는 완료 대신 확인 필요 안내를 표시합니다. 서버에 요청 자체를 전달하지 못한 경우 자동 삭제를 보장할 수 없습니다. ‘기존 백업 갱신’의 로컬 변환 중단은 기존 원본을 보존하는 별도 안내를 사용합니다.

오프라인 목록 제목의 밑줄을 제거했습니다. 마우스를 올리거나 키보드로 제목에 초점을 두면 행 전체를 연한 파랑(`#eaf3ff`)으로 표시합니다. 이전 보관함도 **보관함 열기**로 열면 원본을 바꾸지 않고 화면을 갱신합니다. 이미 저장한 index.html을 직접 여는 것만으로 파일이 새 스타일로 수정되지는 않습니다.

새 백업을 시작할 때 **‘처음부터 전체 백업’** 또는 **‘이전 백업 이후 추가·변경분’**을 선택합니다. 변경분을 선택했다면 정상 완료한 본인의 이전 백업 폴더를 지정합니다. 날짜가 아니라 메일 원본 파일의 이름·크기·SHA-256을 비교하므로 오래된 Date 헤더를 가진 새 메일도 놓치지 않습니다. 변경 없는 메일 파일은 서버 전송 ZIP에서 제외하고 PC의 이전 백업에서 복사·검증합니다. 결과는 과거 백업에 의존하는 링크 없이 원본·색인·첨부를 모두 가진 새 폴더로 저장하고 이전 백업은 수정하지 않습니다. 몇 달 전 백업도 비교 기준으로 선택할 수 있습니다.

**메일 파일 단위 비교입니다.** MBOX에 새 메일이 추가되면 해당 MBOX 전체를 다시 전송합니다. 서버는 파일 비교를 위해 현재 메일을 읽고 복사하므로 서버 읽기·임시 공간까지 없어지는 방식은 아닙니다. 결재는 예전 문서의 수정·상태 변경을 반영하기 위해 현재 DB를 다시 조회합니다. 새 폴더는 현재 서버 목록을 반영하며 서버에서 사라진 메일은 이전 백업에 남습니다. 이전 백업이 손상됐거나 다른 직원의 것이면 거부합니다. 비교 목록은 1,000개·48,000바이트 한도이며 초과 시 전체 백업을 선택하도록 안내합니다. 새 독립 폴더와 메일 첨부를 만들 PC 공간도 필요합니다.

이번 기능은 **Windows v0.6.0과 서버 공용 tools를 함께 갱신**해야 합니다. [서버 설치 명령](tools/README.md#v060-변경분-백업중단-후-자동-정리)을 실행하고 `mail-hash-delta-1`·`cancel-discard-1`을 확인하세요. 그룹웨어 재부팅은 필요하지 않습니다. 서버 갱신 없이도 기존 전체 백업은 가능하지만 변경분 백업은 시작하지 않으며 중단 후 자동 정리 보장은 적용되지 않습니다.

## 추출 대기 중 HTTP 404 · v0.5.9

v0.5.9는 상태 조회가 HTML·일반 텍스트·빈 본문의 HTTP 404를 반환하면 같은 작업의 상태 GET만 최대 두 번 재시도합니다. 일시 오류가 해소되면 다운로드·검증·서버 임시 자료 정리를 계속합니다. 추출 시작 POST를 다시 보내거나 새 작업으로 바꾸지 않습니다. 로그인 화면·PHP 소스·PHP 오류는 즉시 거부하며, 서버가 JSON으로 `job_not_found`를 명시하면 같은 작업을 반복 조회하지 않습니다.

404가 계속되면 같은 인증 연결의 `info` GET을 한 번 점검해 로그인 연결 정상·연결 경로 404·로그인 재확인 필요·서버 설정 오류·점검 실패를 구분합니다. 오류 JSON의 `response`에는 원래 상태 조회 결과를 유지하고, `status_checks`에는 조회 횟수와 연결 점검 결과를 추가합니다. 응답 본문·쿠키·직원 ID·작업 번호·주소·암호는 기록하지 않습니다. 연결 점검도 새 백업을 시작하지 않으며, 영구적인 404를 백업 완료로 처리하지 않습니다.

운영 자료에서 확인된 오류는 v0.5.8의 상태 조회 HTTP 404 / text/html입니다. 사용자 SSH 진단에서는 비공개 설정·작업 폴더 쓰기·DB 연결이 정상이고, 세 주소의 기본 연결 기능도 JSON을 반환했습니다. 이 결과만으로 당시 상태 요청이 404였던 서버 측 원인은 확정할 수 없습니다. 서버 `cancelled / packing` 기록은 압축 단계 중단 기록이며 404 원인과 같다고 단정하지 않습니다. 재발하면 새 `last-client-failure.json`의 상태 조회·연결 점검 결과와 같은 시각의 웹 서버 기록을 확인합니다.

Windows 프로그램만 v0.5.9로 갱신하세요. 서버 공용 tools는 v0.5.7·v0.5.8과 동일하므로 해당 서버 설치를 마쳤다면 재설치·재부팅이 필요하지 않습니다.

## 실행 창 최소화·서버 설정 오류 확인

v0.5.8은 백업 프로그램의 메인 창을 표시하고, `run_windows.bat`의 커맨드 창을 작업표시줄로 최소화합니다. 자동 로그인용 웹 창도 실행 직후 최소화하고 로그인 후 다시 적용합니다. ‘열린 브라우저에서 직접 로그인’을 선택했다면 입력할 수 있도록 로그인 창을 표시하며, 본인 인증 확인 후 최소화합니다. 최소화한 창은 작업표시줄에서 다시 열 수 있습니다. 개인 브라우저 창이나 프로필을 찾아 조작하지 않고 프로그램이 연 브라우저 창만 대상으로 합니다. 창 최소화에 실패해도 수집은 계속합니다. 설치·실행 오류로 커맨드 창이 대기 중이면 작업표시줄에서 열어 오류를 확인하세요.

`service_not_configured`는 직원 로그인 뒤 서버 추출 설정을 확인하지 못했다는 뜻입니다. v0.5.8의 `last-client-failure.json`에는 이 코드와 HTTP 상태·허용된 `server_checks` 참/거짓 값만 저장해 파일 존재·읽기·JSON 해석·PHP 제한 여부를 구분합니다. 설정 경로·설정값·암호·응답 원문은 기록하지 않습니다.

이번 운영 확인에서는 웹 `live.php`가 참조하는 `/home/segio/cell000/etc/segio-live-archive` 폴더 전체가 없는 상태였습니다. 사용자가 v0.5.7 서버 묶음으로 재설치를 완료했습니다. 폴더가 없어진 원인을 확정한 것은 아닙니다. v0.5.8의 공용 서버 도구는 v0.5.7과 동일하므로 이 재설치가 끝났다면 Windows 프로그램만 갱신합니다. 같은 증상이 반복되면 새 익명 오류 JSON과 실제 설치 경로를 확인하며, 서버의 config.json 원문을 전달하지 마세요.

## 백업 후 서버 임시 ZIP 삭제

v0.5.7은 **Windows 프로그램과 서버 공용 tools를 함께 갱신**합니다. [서버 설치 명령](tools/README.md#백업-후-서버-임시-zip-삭제)을 실행한 뒤 `Server cleanup revision: verified-cleanup-1.`을 확인하세요. 각 직원도 v0.5.7을 사용해야 긴 작업 뒤 인증 토큰 갱신과 삭제 확인이 적용됩니다.

PC에서 ZIP의 SHA-256·내부 파일·직원 및 작업 정보 검증을 마치고 원본을 정식 저장 폴더에 보존하면, **메일 본문·첨부 생성 전에 서버의 이번 작업 ZIP과 임시 작업 폴더를 삭제**합니다. 삭제 직전에 새 인증 토큰을 받고 해당 직원의 해당 작업만 정리합니다. 원본 결재·메일은 유지하며 다른 직원의 작업을 이 삭제 요청으로 지우지 않습니다. 로그의 **‘서버 임시 ZIP과 이번 작업 폴더 삭제를 확인했습니다.’**를 확인하세요.

서버는 실제 삭제 결과를 검사하고 삭제 응답을 놓친 경우에도 같은 작업의 요청을 재시도할 수 있습니다. 한 백업에서 최대 세 번 요청합니다. 계속 실패하면 PC 백업을 유지하고 **‘PC 백업 완료 · 서버 임시 ZIP 삭제 미확인’** 경고를 표시합니다. 보관 폴더 `manifest.json`의 `server_cleanup`에는 `deleted` 또는 `pending` 상태와 허용된 오류 코드만 기록합니다. 실행 중인 추출 작업의 중단 요청을 삭제 완료로 표시하지 않습니다.

서버에는 재시도 인증용 작은 `jobs/.작업번호.cleanup.json`이 남을 수 있습니다. 이 파일은 직원·작업 식별자와 정리 상태만 담으며 메일·결재·암호·세션 토큰·ZIP은 담지 않습니다. 작업 폴더가 삭제된 확인 기록과 기존 잔여 종료 작업은 생성 후 24시간이 지나면 다음 백업 시작 시 정리합니다. 예약된 시간마다 실행되는 삭제 작업은 아닙니다. 프로그램 강제 종료·서버 통신 불가 상태에서 즉시 삭제를 보장할 수는 없으며, 기존 ZIP의 백업 완료 여부는 오래된 `ready` 상태만으로 확인되지 않습니다.

## Windows 파일 접근 거부·색인 복구

v0.5.6의 Windows 파일 처리 보완은 v0.5.7에도 포함합니다. 서버 임시 ZIP 삭제 확인은 위 안내에 따라 서버 도구도 갱신하세요. `FILE_ACCESS_DENIED`는 PC 파일 작업이 거부됐다는 뜻입니다. 기존 기록만으로 잠금을 건 프로그램이나 권한·보호 정책의 정확한 원인을 확정할 수는 없습니다.

개인 로그인 백업은 내려받은 자료를 새 `segio-ID` 폴더에 검증하고 그 폴더 안에서 색인·메일 본문·첨부를 생성합니다. 검증 완료 후 로컬 오류가 나도 원본을 임시 폴더 정리로 지우거나 열린 파일을 다른 폴더로 옮기지 않습니다. 미완료 상태를 기록하고 오류 팝업에 저장 위치를 표시합니다. **‘기존 백업 갱신’에서 해당 폴더를 선택**하면 서버에서 다시 받지 않고 로컬 처리를 재실행합니다. 기존 v0.5.2~0.5.5의 `segio-ID-partial` 폴더도 처리합니다. 이미 삭제된 이전 임시 자료를 복원하는 기능은 아닙니다.

명시적인 Windows 공유·잠금 오류 32/33에 한해 파일 교체를 최대 네 번 재시도합니다. 일반적인 접근 거부 5·권한 문제는 반복하지 않고 중단하며 권한이나 보안 설정을 변경하지 않습니다. 메타데이터는 고유 임시 파일을 닫은 뒤 교체하고, 예외가 나도 MBOX 읽기와 SQLite 커서를 닫습니다. 메일 확장자 변경과 메타데이터 갱신 사이에 중단됐다면 기존 manifest의 SHA-256으로 동일 원본인지 검증한 뒤 복구합니다.

새 `last-client-failure.json`의 `filesystem`에는 허용된 예외 종류·`errno`·`winerror`·작업 종류만 추가됩니다. 개인 파일명·경로·메일 내용·예외 원문은 저장하지 않습니다. 오류가 반복되면 팝업에서 안내한 폴더를 보존하고 이 JSON 내용을 확인하세요. 영구적인 권한 문제는 쓰기 가능한 다른 로컬 저장 폴더를 사용하거나 실제 차단 원인을 해결해야 합니다. Windows 프로그램은 Python 3.12의 `run_windows.bat` 또는 해당 버전의 성공한 Windows 빌드를 사용합니다.

## 서버 응답 오류 기록

접속 기본 주소는 `http://lssgroup.co.kr/icons/app/cms/?html=/home/login.html&shell=/index.shell:483`입니다. v0.5.4부터 Windows 프로그램이 아래 오류 기록을 저장합니다.

추출 대기 중 상태 조회가 시간 초과·연결 끊김·일부 HTTP 5xx/408/429 응답으로 실패하면 최대 두 번 재시도합니다. 추출을 시작하는 POST 요청은 재전송하지 않습니다. 로그인 화면이나 PHP 오류·PHP 소스 응답은 재시도하지 않고 표시합니다. JSON 형식과 로그인 사용자 검증은 유지합니다.

오류가 나면 선택한 **Windows 저장 폴더의 `last-client-failure.json`**에 최초 오류 코드·요청 단계·HTTP 상태·응답 형식을 저장하고 팝업에 파일 위치를 표시합니다. 서버 작업 정리 후 서버 로그에 `cancelled`가 남아도 Windows 기록으로 원래 응답 오류를 확인할 수 있습니다. 캡처를 놓쳤다면 이 파일 내용을 보내세요. 응답 본문·쿠키·암호·직원 ID·URL·예외 원문은 기록하지 않습니다. 현재 정보만으로 운영 서버가 HTML을 반환한 정확한 원인을 확정한 것은 아닙니다.

## 진행바·메일 변경 자동 재시도

v0.5.5는 현재 단계와 처리 용량·건수, **현재 단계의 퍼센트**, 전체 경과 시간을 표시합니다. 메일 복사·다운로드·원본 검증·메일 색인·본문 및 첨부 생성은 확인된 처리량을 사용합니다. 결재 DB 추출처럼 총량을 알 수 없는 단계는 움직이는 대기 표시를 사용하고, 서버 ZIP 생성은 실제 생성 용량을 표시합니다. 백업 폴더 저장까지 끝나야 완료로 표시하며 오류·중단을 완료로 표시하지 않습니다. 진행률은 전체 작업 시간의 예측치가 아닙니다.

서버 메일이 복사 도중 변경되면 변경된 파일만 최대 두 번 다시 복사합니다. 변경되지 않은 파일은 재사용하고, 새 파일·삭제·이름 변경도 다시 대조합니다. 계속 바뀌면 `mail_changed_retry`로 중단하므로 메일 이동·정리를 멈추거나 사용량이 적은 시간에 실행하세요. 원본의 일부만 잘라 완료로 처리하지 않습니다.

**Windows 프로그램과 서버 공용 tools를 모두 갱신**해야 메일 재시도와 서버 처리량을 함께 사용할 수 있습니다. 서버 설치 방법은 [공용 tools 안내](tools/README.md#메일-변경-자동-재시도진행률)를 따르세요. 검사·설치 결과의 `Mail copy revision: mail-retry-progress-1.`을 확인합니다. 그룹웨어 재부팅은 필요하지 않습니다. 기존 서버 도구에서는 단계 표시와 PC 처리량만 표시됩니다.

## 대용량 메일함

50GB급 메일함은 **NTFS 또는 exFAT 드라이브에 여유 공간 200GB 이상**을 권장합니다. 원본·전송용 임시 ZIP·열람용 첨부와 파일 수에 따른 공간이 필요하므로 실제 필요량은 달라집니다. 서버에도 원본 복사와 ZIP 생성을 위한 여유 공간이 필요합니다.

메일 전체 본문이나 첨부를 메모리에 쌓지 않고, 원본 위치를 SQLite에 기록한 뒤 메일별로 처리합니다. 32MiB를 넘는 메일도 첨부를 스트리밍 추출하며, 아주 큰 본문은 메일당 합계 8MiB까지 미리 보고 전체 내용은 원본 MBOX/EML에 보존합니다. ZIP64·SHA-256 검증을 유지하고 다운로드·압축 해제 검증이 끝나면 임시 ZIP부터 삭제합니다. 서버 추출 대기는 최대 72시간이며 다운로드 진행 용량을 로그에 표시합니다.

**다운로드·원본 검증 후 로컬 색인이 실패하거나 중단되면** 검증된 원본을 `segio-아이디-partial` 폴더에 남깁니다. 공간을 확보한 뒤 **기존 백업 갱신**에서 이 폴더를 선택하면 서버에서 다시 받지 않고 재처리합니다. 완료된 메일의 열람 파일은 검증 후 재사용합니다. 다운로드 연결 자체가 끊기거나 검증에 실패한 경우는 다시 수집해야 합니다.

## 백업 폴더의 index.html

- **기안일자:** 결재 목록에 원본 DB의 기안일자(`wdate`, 한국 시간)를 표시하고 최신순으로 정렬합니다. 날짜를 확인할 수 없는 문서는 마지막에 `기안일자 미상`으로 표시합니다.
- **검색 범위:** 검색창에서 전체·결재·메일을 선택합니다. 검색 옆의 전체 목록 버튼은 제거했습니다. 검색어를 비우고 검색하면 선택한 범위의 목록이 표시됩니다.
- **문서 열람:** 보관함 목록·원본 DB 기록은 설명 툴팁이 있는 아이콘입니다. 첨부는 새 탭으로 열고, 브라우저가 표시하지 못하는 형식은 다운로드합니다. 인코딩된 사인 이미지를 복원하며, 복원 불가능한 사인은 긴 문자열 대신 `서명 이미지 미확보`로 표시합니다.
- **메일:** 받은편지함·보낸편지함과 원래 사용자 지정 보관함을 상단 메뉴로 선택합니다. 파일·보관함 이름으로 분류하고 발신 주소로 추정하지 않습니다.
- **날짜:** 제목 옆에 원본 메일의 `Date` 헤더 날짜·시간대를 표시하고, 시간대를 확인할 수 있는 날짜를 최신순으로 정렬합니다. 이동·다운로드·백업 시각으로 대체하지 않습니다. 없는 날짜는 `날짜 미상`입니다.
- **결재:** 완료문서·반려문서·참조문서·수신문서·진행문서·임시문서·상태 미확인을 상단 메뉴로 선택합니다. 참조·수신 관계는 상태와 중복될 수 있습니다. 뜻이 확인되지 않은 숫자 상태 코드는 임의로 완료·반려로 분류하지 않습니다.
- 검색·건수·100건 단위 페이지 이동은 선택한 분류에 적용됩니다. 백업 폴더 전체를 유지하면 서버와 연결하지 않고 사용할 수 있습니다.

**기존 백업은 새 프로그램의 ‘기존 백업 갱신’ 또는 ‘보관함 열기’에서 폴더를 선택하세요.** 이미 받은 원본 DB 기록·첨부·SQLite를 유지하면서 인덱스와 결재 표시용 HTML을 갱신하고 파일 검증 목록도 함께 갱신합니다. 서버에서 다시 다운로드하거나 서버 도구를 재설치할 필요는 없습니다. 기존에 따로 만든 ZIP은 갱신하지 않습니다.

두 프로그램의 서버 도구는 [공용 tools 안내](tools/README.md)를 참고하세요. 아래는 기존 관리자 SSH 방식의 상세 안내입니다.

## 다른 수집 방식과 보관 범위

관리자 SSH 백업과 웹 화면 수집의 명령줄 기능은 유지합니다. [SSH 사용 안내](docs/SSH_ARCHIVE.md)와 [개인 로그인 연결 안내](docs/WINDOWS_LOGIN.md)를 참고하세요. 개인 DB·MBOX 방식은 로그인한 직원의 관계로 연결되는 결재와 본인 메일을 가져옵니다. 전체 서버 DB 복제나 원래 SEGIO 화면별 권한과 동일하다고 검증한 기능은 아닙니다. 암호·쿠키는 백업이나 설정에 저장하지 않습니다.

폴더의 `index.html`, `search`, `documents`, `mail`, `catalog.sqlite3`, `manifest.json`을 함께 보관하세요. 원본 MBOX와 첨부를 보존하며 서버의 계정이나 자료를 삭제하지 않습니다.

## 개발·검증

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
SEGIO_TEST_PHP=php .venv/bin/python tools/run_ci_tests.py
```

기존 Chromium을 쓰는 경우 `SEGIO_TEST_BROWSER`에 실행 파일 경로를 지정합니다. Windows 패키지는 Windows에서 `build_windows.ps1`로 빌드합니다. 이번 검사 결과와 운영 서버·Windows 현장 확인 범위는 [VALIDATION.md](VALIDATION.md)를 참고하세요.
